# 三晋智行

> 表里山河 · 文旅定制平台

以**自建三晋方志知识库（RAG）**与大模型为笔，为旅行者编排古建、佛艺、晋商、非遗、山川、风味的智能行程定制与对话咨询服务。

核心主张：**地理准确**。行程不会出现「朔州吃平遥牛肉」这类张冠李戴。

---

## 项目简介

三晋智行是一个面向山西文旅的智能行程定制平台。用户选择想去的府邑、天数、节奏与意趣，平台基于一部自建的结构化三晋方志知识库，结合大模型生成逐日行程；同时提供「驿路谋士」对话咨询，回答关于山西景点、特产的问题。

项目的关键工程问题是**地理归属的准确性**——大模型知道「平遥牛肉是晋中平遥特产」，但生成长文时仍可能把它写进朔州的餐食。因此本项目不依赖模型自觉，而是用**三道闸门 + 一道兜底**保证结果的地理正确性（详见下文「准确性设计」）。

## 核心功能

| 功能 | 说明 |
|------|------|
| **华夏定制**（行程生成） | 选择府邑 / 天数 / 同行人 / 节奏 / 意趣，生成逐日行程；支持重新生成、来源标识（大模型 / 缓存 / 兜底） |
| **驿路谋士**（智能体对话） | SSE 流式对话，检索知识库问答对后由大模型作答；未配置 Key 时自动降级为本地应答 |
| **三晋方志**（知识库浏览） | 按府邑 / 分类筛选 + FTS5 全文检索，景点附百度百科词条直链 |
| **典藏线路** | 18 条策展线路（10 条官方红色旅游线路 + 8 条主题线路），可一键套用到行程表单 |
| **三晋山河舆图** | 高德地图标注 11 个府邑，按所选目的地高亮并绘制行程动线 |
| **我的通关文牒** | 已保存行程的载入 / 删除；行程按用户隔离 |
| **行驿日程** | 摘要 + 逐日详情 + 手工编辑 + PDF 导出 |
| **账号体系** | 登录 / 注册（图形验证码 + IP 限流 + 密码强度提示），JWT 会话，bcrypt 密码哈希 |
| **移动端适配** | 窄屏自动切换底部标签栏导航，375 / 390 / 412 三档宽度零横向溢出 |

## 技术栈

| 层级 | 技术 |
|------|------|
| 前端 | Vue 3 + Vite 5 + TypeScript + Tailwind CSS 3 + Pinia + Vue Router 4 |
| 后端 | FastAPI + SQLAlchemy 2.0 + Pydantic v2（pydantic-settings） |
| 数据库 | SQLite（FTS5 全文索引），可切换 PostgreSQL / MySQL |
| 认证 | JWT（python-jose）+ bcrypt 密码哈希 + Pillow 图形验证码 + IP 限流 |
| 检索 | 结构化召回（府邑 → 景点 / 特产）+ SQLite FTS5 全文检索（无需向量库） |
| 大模型 | DeepSeek：行程生成用推理模型，对话用 `deepseek-chat`（非推理，首字延迟低） |
| 地图 | 高德地图 JS API 2.0 |
| 测试 | pytest（114 项）+ 接口冒烟 + 知识库 / 提示词校验脚本 |

## 准确性设计：三道闸门 + 一道兜底

```
用户表单
   │
   ├─ ① 提示词接地（RAG）
   │     从知识库取出该府邑的真实景点与本地特产注入提示词，
   │     声明「不得使用该日城市之外的景点或特产」，并给出逐日城市对照表
   │
   ├─ ② 结果审计（大模型第二角色）
   │     以「山西文旅地理审核员」身份复核生成的行程，
   │     独立报告特产产地错配 / 域外城市提及
   │
   └─ ③ 代码规则兜底（确定性，不依赖模型）
         特产产地 ≠ 当日城市 → 自动替换为该城真实特产；
         替换建议必须能在知识库中查到，否则丢弃
```

即使大模型完全不可用，第 ④ 层兜底行程也由知识库条目组装，**天然不存在地理错配**——即接口永不返回张冠李戴的行程。

实测 4 个代表性用例（含原始 bug 场景「朔州 2 日 · 风味」）地理错配残留 **0 处**。

## 知识库（RAG）

一部人工整理、逐条标注真实所在地的三晋方志：

- **11 个府邑**（太原 / 大同 / 朔州 / 忻州 / 晋中 / 吕梁 / 阳泉 / 长治 / 晋城 / 临汾 / 运城）
- **98 条景点**，按主题分为八类：古建营造、佛教艺术、晋商精神、非遗、山川自然、风味美食、红色记忆、博物馆藏
- **49 条特产**，含正宗产地与别名（如「平遥牛肉」→ 晋中，「浑源凉粉」→ 大同）
- 导出 **189 条问答对**（`knowledge_txt/`），供「驿路谋士」对话检索使用

数据唯一起点是 `backend/data/knowledge_seed.json`，编辑后经 `backend/scripts/import_knowledge.py` 校验导入；内容变化会自动改变知识库指纹，行程缓存随之失效。详细维护方式见 [knowledge_txt/README.md](./knowledge_txt/README.md)。

## 本地运行

### 环境准备

- Python >= 3.10（建议虚拟环境）
- Node.js >= 18（仅构建前端时需要）

### 配置密钥

密钥一律通过环境变量注入，**不进入版本库**：

```bash
# 后端：复制模板后填入
cp backend/.env.example backend/.env
#   DEEPSEEK_API_KEY     大模型 Key（留空则行程生成自动走知识库兜底，对话走本地降级应答）
#   ADMIN_PASSWORD       管理员密码（务必修改默认占位值）

# 前端：高德地图 Key（三晋山河舆图使用，申请时选「Web端(JS API)」）
cp frontend/.env.example frontend/.env
```

### 启动

最省事的方式——后端会顺带托管前端构建产物，一个进程一个地址就是完整站点：

```bash
cd frontend && npm install && npm run build   # 首次需构建
cd ../backend && python run.py
```

打开 **http://localhost:8000/** 即可使用（前后端同端口），启动面板会打印接口文档（`/docs`）与探活（`/api/health`）入口。

需要前端热更新时改用两个终端：

```bash
# 终端 1 —— 后端
cd backend && python -m uvicorn app.main:app --reload --port 8000

# 终端 2 —— 前端
cd frontend && npm run dev        # http://localhost:5173
```

### 运行测试

```bash
cd backend
python -m pytest tests -q         # 114 项
python scripts/smoke_api.py       # 接口冒烟（不调用大模型）
```

## 设计取舍

- **不用向量库**：结构化召回（府邑 → 景点 / 特产）+ SQLite FTS5 即可满足知识库规模，零额外依赖；对话侧用「城市优先 + 中文二元组词面打分」召回问答对。
- **对话不用推理模型**：推理模型先输出思维链、首字延迟高；行程生成需要规划能力，故用推理模型，两者各司其职。
- **失败即降级，接口永不 500**：未配置 Key 或调用失败时返回知识库兜底内容 / 本地应答，并明确告知当前处于降级状态。
- **单进程部署**：后端直接托管前端产物，线上只需一个 Python 进程，不必装 Node、不必配 Nginx。

## 安全说明

- `backend/.env`、`frontend/.env`、本地数据库、构建产物均已在 `.gitignore` 中排除，请勿将任何真实密钥提交到版本库。
- 首次部署务必通过 `.env` 修改 `ADMIN_PASSWORD` 与 `JWT_SECRET_KEY`。
- 若曾在其它地方分享过本项目代码，请轮换其中出现过的 API Key。
