| 文件 | 大小 | 内容 |
|------|------|------|
| `三晋智行_全量知识库（问答对）.txt` | 107 KB | **推荐导入这个**，189 条问答对 |
| `三晋智行_景点问答对.txt` | 27 KB | 50 条，仅景点 |
| `三晋智行_特产问答对.txt` | 33 KB | 60 条，仅特产风味 |

### 方案二：列表形式（备用）

| 文件 | 大小 | 内容 |
|------|------|------|
| `三晋智行_全量知识库.txt` | 57 KB | 88 条结构化条目 |

## 二、为什么问答对更好

讯飞知识库检索结果的 `answerSource` 字段分三类（官方接口文档明确标注）：

| 取值 | 含义 | 准确度 |
|------|------|--------|
| `qa` | 问答对 | **100% 准确** |
| `spark` | 星火模型 | 100% 准确 |
| `doc` | 文档问答 | **不是 100% 准确** |

问答对形式把这批资料推向 `qa` 通路，而不是让模型从长文档里"读"出答案。

另外三个实际好处：

1. **问句直接对齐**：用户问「大同有哪些景点？」，语料里就有字面对应的一条，关键词与向量两路都好命中。
2. **分片边界干净**：一条问答对 = 一个完整 chunk，天然不会把两个城市的内容切进同一片。
3. **答案自带归属地**：每个答案首句就写明「XX是山西YY的特产」，即使只召回一条也不会认错地方。

### 问答对的四种类型

导出的 189 条覆盖了用户真实会问的四类问题：

| 类型 | 示例问句 | 条数 |
|------|---------|------|
| 府邑汇总 | 大同有哪些景点？／大同有什么好玩的地方？ | 22（11 城 × 景点/特产） |
| 单条景点 | 应县木塔在哪里？／云冈石窟值得去吗？ | 39 |
| 单条特产 | 右玉羊肉是哪里的特产？／冠云牛肉是什么？ | 49 |
| **易混淆专问** | 平遥牛肉是朔州的特产吗？ | 8 |
| 山西总览 | 山西有哪些地级市？ | 1 |

第四类「易混淆专问」是专门为你之前踩过的坑设计的，直接给出否定式答案：

```
问：平遥牛肉是哪里的特产？／平遥牛肉是朔州的特产吗？
答：平遥牛肉是山西晋中的特产，不是朔州、大同的特产。平遥传统名产，经腌、卤、焖
    多道工序制成，肉色红润、纹理清晰，入口酥烂不柴、咸香回甘，明清时已是晋商
    行销四方的名品。
```

同一答案的多种问法（「哪里产的」「是什么」「XX是不是」）合并在同一行问句里，
用 `／` 分隔 —— 这样既覆盖多种问法，又不会让语料重复膨胀。

## 三、导入步骤

1. 讯飞星火智能体平台 → **知识库** → 新建知识库
   - 名称建议：`三晋文旅方志`
   - 类型：文档知识库
2. 进入知识库 → **导入数据** → 选择「**导入文本文件**」（就是你截图里那个选项）
3. 拖入 `三晋智行_全量知识库（问答对）.txt`，等待解析
4. 解析完成后，**检查分片结果**（关键步骤）：
   - 抽看 3–5 个切片，确认每片正好是「问：… 答：…」的完整一对
   - 确认没有把两条不同城市的内容切进同一片
   - 若出现「问」与「答」被切开，说明分段过碎 → 改用**自定义分段**
5. 确认无误后**发布 / 启用**该版本（工作流只能检索已启用版本）

> 「导入网站链接」用不上 —— 本知识库无线上来源。

### 分段设置

本导出文件已按分片友好格式组织：

- `====` 分隔四大板块；`----` 分隔各府邑
- **每条问答对之间用空行分隔**，且「问：」与「答：」在相邻两行

**优先用自动分段**，多数情况下平台会按空行切出完整的问答对。

若自动分段效果不佳，用**自定义分段**，分段标识填**空行**（或在支持的平台上选「按段落分段」）。
目标是让每片 = 一条完整问答对。

> 若平台提供 **「问答库 / 问答对」类型**的知识库（部分版本在「新增」里有独立入口），
> 可把问答对按「问题 / 答案」两列录入。本目录的 txt 每行 `问：` / `答：` 结构也便于转换。

## 四、工作流搭建

### 4.1 整体结构

```
开始节点
   ↓  (用户问题)
知识检索节点        ← 接入「三晋文旅方志」知识库
   ↓  (results: 召回片段)
通用大模型节点      ← 用下方提示词，把召回内容作为依据
   ↓  (text: 回答)
结束节点
```

四个节点，一条直线。不需要 Coze。

### 4.2 各节点配置

**① 开始节点**

| 参数 | 标识 | 类型 | 说明 |
|------|------|------|------|
| 用户问题 | 如 `query` | String | 设为必填，后面引用它 |

**② 知识检索节点**

参考官方文档 [知识检索](https://flames.iflytek.com:2443/agent/docs/components/index/knowledge-search.html)，
选**「知识库文档」**形态（参数最全）：

| 参数 | 标识 | 配置值 | 理由 |
|------|------|--------|------|
| 查询 | `text` | `{{开始节点.query}}` | 直接透传用户问题 |
| 知识库 | `dbNames` | 勾选「三晋文旅方志」 | — |
| 向量结果 | `embeddingTop` | **5** | 问答对偏短，5 条足够 |
| 向量阈值 | `thresholdScore` | **0.3 ~ 0.4** | 问答对文本短，阈值可比长文档略低 |
| 关键词结果 | `esTop` | **3（别设 0）** | 「平遥牛肉」「应县木塔」靠关键词命中更准 |
| QA 相似度阈值 | `qaThresholdScore` | **0.85 ~ 0.9** | 若你的版本支持问答对召回，用这个控制精度 |

> **两个关键点**：
> 1. `esTop` 不要设 0。中文地名与菜名是精确词，关键词检索比向量更可靠，两路混召才稳。
> 2. 用了问答对语料后，`thresholdScore` 可以比长文档场景调低一点（0.3 起试），
>    因为每条问答对本身信息密度高，多召回几条也不会互相干扰。

**③ 通用大模型节点**

参考 [通用大模型](https://flames.iflytek.com:2443/agent/docs/components/llm/llm.html)：

| 参数 | 标识 | 配置值 |
|------|------|--------|
| 模型 | `domain` | 星火通用模型（如 `4.0Ultra`，按你账号可用范围） |
| 提示词 | `prompt` | 见 4.3，替换 `{{}}` 变量 |
| 温度 | `temperature` | **0.2**（知识问答要稳，不要发挥） |
| topK | `topK` | **3** |

> 温度务必调低。旅游知识问答不需要创造力，0.1–0.3 最稳。

**④ 结束节点**

| 参数 | 类型 | 值 |
|------|------|-----|
| 回答 | String | `{{大模型节点.text}}` |

### 4.3 提示词（直接复制，替换两个变量）

完整提示词（含人设、范围边界、闲聊应答、防编造规则与验收示例）已单独整理：

> **[../prompts/讯飞大模型节点提示词.md](../prompts/讯飞大模型节点提示词.md)**
>
> 里面分「系统提示词」与「用户提示词」两段，可直接复制到大模型节点对应输入框。
> 要点：
> - 人设「驿路谋士」，称用户为「行者」，自称「在下」/「某」
> - **回答范围限山西**，域外问题礼貌说明后引导回三晋话题
> - 闲聊寒暄热情回应，顺势提一句山西，不硬拉回
> - 地理归属硬约束（点名平遥牛肉属晋中、不得说成朔州）
> - 资料未收录须说明「方志未收录」，**不得编造价位／票价／年代**
> - 敏感话题婉谢不展开

若想自己从零写，最小可用版本如下（变量按实际替换）：

```text
你是「驿路谋士」，三晋（山西）文旅方志的讲解助手。称用户为「行者」。

【范围】只答山西文旅：景点、古建、佛艺、晋商、非遗、山川、风味、行程宜忌。
域外话题礼貌说明后引导回山西；闲聊热情回应，顺势提一句三晋风物；
政治宗教民族军事等敏感议题婉谢。

【事实】只依下方资料作答。资料未收录就说「现有方志未收录」，
可给方向性建议但须说明是建议而非方志记载，绝不编造。
地名物产归属必须准确：平遥牛肉、太谷饼属晋中；浑源凉粉、大同刀削面属大同；
右玉羊肉、应县紫皮蒜属朔州。资料中「不是某某特产」的否定说明必须保留。
标注「同源地区」者要讲清正宗产地。标注「尚待核实」者提示可能存疑。

【风格】先结论后缘由，末尾附一句实用提示；可用并州、平城等雅称；
400 字以内，分段落陈述，不用 Markdown 表格。

【方志资料】
{{知识检索节点.results}}

【行者所问】
{{开始节点.query}}

请依上述资料与规则作答。
```

### 4.4 验收测试（务必跑一遍）

搭好后用这几组问题验证，**第 1 组是历史 bug 场景，必须答对**：

| # | 提问 | 期望 |
|---|------|------|
| 1 | 朔州有什么特产和好吃的？ | 只出现右玉羊肉、应县紫皮蒜、朔州大烩菜等本地货。**绝不能出现平遥牛肉** |
| 2 | 平遥牛肉是哪里的特产？ | 答晋中平遥 |
| 3 | 平遥牛肉是朔州的特产吗？ | 明确否定，答晋中 |
| 4 | 西安有什么好玩的？ | **礼貌说明只管山西，并引导回三晋话题**，不介绍兵马俑等域外景点 |
| 5 | 你好 | 古风得体回应闲聊，顺势提一句山西，不生硬 |
| 6 | 去朔州玩，应县木塔怎么安排？ | 提到仅开放底层、不能登塔 |
| 7 | 大同和朔州各有什么代表美食？ | 两城不混淆 |
| 8 | 朔州有什么米其林餐厅？ | 说明方志未收录，**不得编造餐厅名** |
| 9 | 应县木塔门票多少钱？ | 说明票价方志未载、以官方发布为准，**不得编票价** |

第 3、4、5、8、9 题是重点：分别测否定式问答对、域外引导、闲聊应答、
以及两类「不编造」（编餐厅名、编票价）。
更完整的对照示例见 [../prompts/讯飞大模型节点提示词.md](../prompts/讯飞大模型节点提示词.md) 第四节。

### 4.5 常见问题

| 现象 | 原因 | 处理 |
|------|------|------|
| 回答总说「未收录」 | 阈值过高或 `esTop=0` | `thresholdScore` 降到 0.3，`esTop` 设 3 |
| 「问」和「答」被切成两片 | 分段过碎 | 改自定义分段/按段落，目标每片一条完整问答对 |
| 回答混入其它城市特产 | 阈值过低 | 阈值提到 0.45+；或改用 `by_city/` 分库 |
| 检索不到具体菜名 | 纯向量对专有名词弱 | 确认 `esTop` > 0 |
| 改了知识库但回答没变 | 知识库未重新发布；工作流绑旧版本 | 重新发布并启用新版本 |

## 五、接回本项目（已完成）

工作流已接入项目的「驿路谋士」页面。**实际用的是 HTTP 接口，不是 WebSocket** ——
截图里的 `接口地址` 指向的是星辰 Workflow OpenAPI：

| 项 | 值 |
|----|----|
| 请求地址 | `https://xingchen-api.xf-yun.com/workflow/v1/chat/completions` |
| 鉴权 | Header `Authorization: Bearer {API_KEY}:{API_SECRET}` |
| 请求体 | `{"flow_id":…, "uid":…, "parameters":{"AGENT_USER_INPUT":…}, "stream":false}` |
| 响应 | `choices[0].delta.content` 为回答正文 |

参考 [星火智能体 Workflow Open API 文档](https://www.xfyun.cn/doc/spark/workflow.html)。

### 已完成的代码改动

| 位置 | 内容 |
|------|------|
| `backend/.env` | 新增 `XINGCHEN_API_KEY` / `XINGCHEN_API_SECRET` / `XINGCHEN_FLOW_ID` 等 |
| `backend/app/services/agent_service.py` | 重写为调用星辰工作流；含错误码映射与会话续聊 |
| `backend/app/schemas/agent.py` | 响应新增 `session_id` / `source` / `error` |
| `backend/app/api/agent.py` | 新增 `GET /api/agent/status` 服务状态 |
| `frontend/src/views/AgentView.vue` | 修复历史污染等缺陷，展示真实错误 |
| `frontend/src/api/index.ts` / `types/index.ts` | 补 `loadAgentStatus` 与相关类型 |

### 两个重要实现细节

1. **讯飞在业务错误时仍返回 HTTP 200**，真实错误在 body 的 `code` 字段。
   因此服务端必须显式解析 `code` 并映射为中文提示（已实现 30+ 错误码映射），
   否则前端只会看到一条空回复。
2. **多轮对话**：首次调用返回 `id` 作为会话标识，服务端维护
   `sessionId → chat_id` 映射并回传 `session_id` 给前端；
   前端每个会话持久化该 id，后续轮次带上即可承接上下文。
   同时请求体可传 `history`（严格 `user→assistant` 交替、首元素须为 `user`）。

### 若对话出现降级

项目提供了专门的诊断脚本，逐层排查（配置 → 鉴权 → flow_id → 发布状态 → 授权 → 内容）：

```bash
cd backend
python scripts\diagnose_agent.py
python scripts\diagnose_agent.py --message "朔州有什么特产？"
```

它会打印工作流节点的诊断信息（`inputs` / `outputs` / `executed_time` / `usage`），
便于区分「参数没传进去」与「工作流自身没跑起来」。

响应 `source` 为 `fallback` 时，`error` 字段给出原因。常见情况：

| code | 含义与处置 |
|------|-----------|
| `401` | 鉴权失败。核对 API Key / Secret。**注意「星火大模型」的 `ak-…` Key 不能用于工作流**，两者是独立服务 |
| `460` | `parameters` 为必填，且键名须与开始节点参数名一致 |
| `20201` | flow_id 不存在，核对「智能体 API」页的 API Flowid |
| `20204` / `20207` | 工作流未发布或处于草稿，在平台发布 |
| `20373` | 该 APPID 未被授权调用工作流，或额度用尽。需在控制台为该应用**单独开通「智能体/工作流」服务**（开通星火大模型 ≠ 开通工作流） |
| `20500` / `20501` | 工作流内知识库节点异常（检查知识库是否已挂载、版本是否已启用） |
| `23300` | 工作流内大模型节点失败（多为提示词为空或模型未授权） |
| `20805` | **工作流输出失败**。若 `executed_time=0`、`usage` 全 0，说明工作流未进入执行，属编排/发布问题，而非参数问题。重点查：结束节点是否已连接且返回变量与协议一致、开始节点参数名是否匹配、大模型节点提示词是否为空 |

> 排查 `20805` 最直接的办法：在平台的工作流卡片上点 **「对话」** 按钮。
> 平台内能跑通而 OpenAPI 不行 → 问题在协议绑定或结束节点输出；
> 平台内也跑不通 → 问题在工作流编排本身。

前端页面底部也会提示「当前为本地降级应答」，并展示具体原因。

## 六、重新生成 txt

改完 `backend/data/knowledge_seed.json` 后：

```bash
cd backend

# 1. 校验知识库数据（不通过不要导出）
python scripts\import_knowledge.py --check

# 2. 导入数据库（供项目内 RAG 与知识库页面使用）
python scripts\import_knowledge.py

# 3. 导出问答对 txt（推荐导入讯飞的形式）
python scripts\export_knowledge_qa.py
python scripts\verify_knowledge_qa.py      # 21 项校验

# 4.（可选）导出列表形式 txt
python scripts\export_knowledge_txt.py
python scripts\verify_knowledge_txt.py     # 58 项校验
```

导出脚本能保证（均由校验脚本自动验证）：

**问答对形式**
- 每个「问：」都紧跟非空「答：」，无孤立问句、无悬空答案
- 每条问答对 < 600 字，不会被平台二次切分
- 朔州相关问答对中不混入平遥牛肉等外地名产
- 平遥牛肉明确归属晋中
- 11 个府邑均有景点/特产汇总问
- 无「又称平遥牛肉」这类自指别名

**列表形式**
- 每条内容标题带 `【府邑】`，切分后仍能看出归属地
- 各府邑小节内不混入外城景点/特产
- `by_city/` 各文件条目归属本城
